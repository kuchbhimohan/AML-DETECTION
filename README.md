# Sentinel AML — Transaction Monitoring

**Catches 74.9% of money laundering while reviewing just 1% of bank transfers** — evaluated on 862,792 unseen transfers,
9 points above logistic regression (95% CI +6.5 to +11.3; DeLong p = 3.7×10⁻¹⁴).

Leak-free behavioural features · monotone LightGBM · statistical evaluation (bootstrap, DeLong, McNemar, PSI) ·
isotonic calibration · SHAP reason codes · MLflow · FastAPI · Streamlit dashboard · 79 tests.

**Live demo:** _link added after deployment_ &nbsp;·&nbsp; **Data:** [IBM Transactions for Anti-Money Laundering (HI-Small)](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)

---

## The problem

Laundering is about **1 in 980** transfers, and investigators can review only a small, fixed share. Accuracy is
meaningless here (predicting "never laundering" is 99.9% accurate), so the project is framed as a ranking problem:

> **If investigators review the riskiest k% of transfers, what share of all laundering do they catch?**

The headline metric is **recall at an alert budget** (0.5%, 1%, 2%), with PR-AUC for overall ranking quality.

## Results — untouched test period (Sep 9–10, 2022)

| Model | PR-AUC [95% CI] | Recall @0.5% | Recall @1% [95% CI] | Recall @2% |
|---|---|---|---|---|
| **LightGBM, monotone (champion)** | **0.534** [0.505–0.565] | **66.7%** | **74.9%** [72.2–77.6] | **77.8%** |
| Logistic regression | 0.117 [0.103–0.135] | 52.1% | 65.9% [63.2–69.0] | 74.6% |
| Rules (ACH first, then amount) | 0.012 | 2.0% | 2.1% | 15.5% |

- **Significance:** paired Poisson bootstrap (1,000 resamples) gain of +9.0 points at 1%; DeLong p = 3.7×10⁻¹⁴;
  McNemar p = 8.8×10⁻¹³ (118 laundering cases caught only by the champion vs 32 only by logistic regression).
- **High-risk band:** 572 alerts at 75.7% precision (threshold chosen on validation).
- **Calibration:** isotonic, fitted on validation — alerts scored 50–90% averaged 70.1% predicted vs 69.0% actual.
- **Per pattern:** 96–100% recall on all 8 labelled laundering patterns; 37.5% on unlabelled laundering (the honest weak spot).
- **Other algorithms** (fixed settings, champion unchanged): Random Forest, Extra Trees and an ensemble tie the
  champion; MLP (−5.2 pts), class weighting (−3.6) and logistic (−9.0) are significantly worse.

Full numbers: [`reports/results.md`](reports/results.md) · [`reports/extra_models.md`](reports/extra_models.md).
Every number in this README is regenerated by `uv run python -m aml.evaluate`.

## How it works

```
Kaggle (heavy, once)          Laptop (2 cores, ≤5-minute jobs)                 Outputs
5.08M transfers ──► time split + 38 leak-free features ──► sampled parquet ──► LightGBM + Optuna ──► MLflow registry
                                                                                     │                    │
                                                              reports/results.md ◄── evaluate     FastAPI + dashboard
```

1. **Time split, no leakage.** Train Sep 1–6, validate Sep 7–8, test Sep 9–10. Every feature uses only *strictly earlier*
   transactions — proven by a brute-force equivalence test, a "delete the future changes nothing" test, and a
   0/300-mismatch spot check on real data. A sparse simulator tail (Sep 11–18, 59% laundering) is excluded and reported separately.
2. **Features** (`src/aml/features.py`): velocity, fan-in/fan-out (distinct counterparties), pass-through, pair
   history, reverse flows, amount vs the sender's norm, timing, account type flags — computed in one pass with a
   two-pointer sliding window + hash map (126 s for 5M rows). Amounts converted to USD with rates estimated from training data.
3. **Imbalance:** case-control sampling (all laundering + 8% of normal), then prior correction
   `p = r·p / (r·p + 1 − p)` — ranking unchanged, probabilities back on the real-world scale.
4. **Models:** rules, logistic regression (VIF-pruned, odds ratios with CIs) and Isolation Forest baselines;
   LightGBM / XGBoost tuned with Optuna, every trial in MLflow. **Monotonic constraints** (more velocity or fan-out
   can never lower risk) cost 0.95% PR-AUC on validation and were kept; the champion is registered as `aml-lgbm@champion`.
5. **Evaluation:** paired bootstrap CIs, DeLong, McNemar, Platt vs isotonic calibration (Brier, ECE), cost-based
   thresholds, PSI drift, Wilson CIs for per-pattern recall, and an ablation of the clock-like account-age features.
6. **Explainability:** exact TreeSHAP; every alert gets its top-3 risk-raising reasons in plain English.
7. **Product:** FastAPI (`/score`, `/score/batch`, `/health`, `/model`) and a five-view Streamlit dashboard
   (command center, alert queue, investigation with live SHAP, alert-budget simulator, model lab).

## Run it

```bash
uv sync                                        # pinned environment
uv run pytest                                  # 79 tests
uv run streamlit run app/streamlit_app.py      # dashboard (uses committed demo data + model)
uv run uvicorn api.main:app --port 8000        # API, docs at http://127.0.0.1:8000/docs
```

Rebuilding everything from scratch: run `notebooks/01_eda.ipynb` and `notebooks/02_features.ipynb` on Kaggle
(add the IBM dataset as input), put the outputs in `data/processed/`, then:

```bash
uv run python -m aml.baselines                 # Step 5: baselines -> reports/baselines.md
uv run python -m aml.train tune --model lgbm   # Step 6: Optuna batches (repeat), then --model xgb
uv run python -m aml.train final               # fit champion, register in MLflow
uv run python -m aml.evaluate                  # Step 7: reports/results.md
uv run python -m aml.explain                   # Step 8: reports/explainability.md
uv run python -m aml.demo_data                 # dashboard + API artefacts
uv run mlflow ui --backend-store-uri sqlite:///mlflow.db
```

The pipeline works on other transaction data by editing `configs/schema.yaml`.

## Limitations

- Synthetic data (real AML labels are never public); only 10 usable days, so 7-day features "warm up" during the first week.
- Account age partly measures time since the data starts. Ablation: removing it lowers validation PR-AUC
  (0.574 → 0.522) but leaves recall at 1% almost unchanged (80.9% → 80.1%).
- Only 2-hop cycles are detected; unlabelled laundering is caught 37.5% of the time — next step: longer graph features.
- Features are computed in batch; production would need a streaming feature store.
